# Claude Code Rules for Moto Kitchen Website

## Project Permissions

### Autonomous Operations (No Permission Required)
You are authorized to perform the following operations without asking for permission:

1. **File Operations**
   - Read any file in the project
   - Edit existing files
   - Write new files
   - Delete files (when explicitly requested)
   - Create new directories

2. **Code Operations**
   - Refactor code
   - Fix bugs
   - Add features
   - Update dependencies
   - Run tests
   - Build the project
   - Start development servers

3. **Search & Analysis**
   - Search through codebase
   - Analyze code structure
   - Read documentation
   - Explore file systems

4. **Database Operations**
   - Read database schemas
   - Suggest SQL queries
   - Provide migration scripts

### Operations Requiring Permission

1. **Git Operations**
   - Creating commits
   - Pushing to remote repositories
   - Creating/merging branches
   - Force pushing
   - **Always ask before: `git push`, `git commit`, `git merge`**

2. **Deployment**
   - Deploying to production
   - Deploying to staging
   - **Always ask before deploying**

3. **Destructive Operations**
   - Dropping databases
   - Deleting production data
   - Revoking credentials
   - **Always ask before destructive operations**

## Project Context

### Tech Stack
- **Framework**: Next.js 14+ (App Router)
- **Language**: TypeScript
- **Styling**: Tailwind CSS
- **Database**: Supabase (PostgreSQL)
- **Payments**: Stripe
- **Email**: Resend
- **Deployment**: Vercel

### Key Directories
- `/app` - Next.js App Router pages and routes
- `/components` - React components
- `/lib` - Utility functions, API clients, helpers
- `/types` - TypeScript type definitions
- `/public` - Static assets

### Important Files
- `/.env.local` - Environment variables (DO NOT commit)
- `/package.json` - Dependencies and scripts
- `/tailwind.config.ts` - Tailwind configuration
- `/tsconfig.json` - TypeScript configuration

### Coding Standards

1. **File Operations**
   - Always prefer editing existing files over creating new ones
   - Use TypeScript for all new files
   - Follow existing code patterns and conventions

2. **Component Structure**
   - Use 'use client' directive for client components
   - Keep server components as default
   - Follow the established component patterns

3. **Styling**
   - Use Tailwind CSS utility classes
   - Use CSS variables for brand colors:
     - `--brand-primary` (#C9653B)
     - `--brand-secondary` (#3A2A24)
     - `--brand-background` (#FAF6EF)
   - Use Inter font: `style={{ fontFamily: 'var(--font-inter), sans-serif' }}`

4. **Admin Pages**
   - All admin pages should use consistent font styling
   - Headers: `text-3xl font-bold` with Inter font, weight 600
   - Descriptions: Inter font, weight 400
   - Don't modify `/app/admin/invoice/page.tsx` unless explicitly requested

5. **Security**
   - Never expose sensitive data
   - Always validate user input
   - Use proper authentication checks
   - Follow OWASP best practices

### Git Workflow
When user requests git operations:
1. Always show `git status` first
2. Show `git diff` for staged changes
3. Review commit messages
4. **ASK FOR PERMISSION before `git push` or `git commit`**

### Testing
- Run tests before committing
- Fix any failing tests
- Ensure TypeScript compiles without errors

### Special Notes
- Invoice generation page should not be modified without explicit request
- Banner components have been removed from order pages for better UX
- Mobile-first responsive design is a priority
- Tenant name in database: "MOTO KITCHEN" (not "MOTO KITCHEN NL")

## Communication Style
- Be concise and technical
- Focus on facts and problem-solving
- Avoid superlatives and excessive praise
- Ask clarifying questions when requirements are ambiguous
- Provide direct, objective technical information

## When to Ask Questions
- When requirements are unclear
- When multiple valid approaches exist
- Before making architectural decisions
- Before modifying critical systems
- **Always before git push/commit**
- **Always before deployment**
